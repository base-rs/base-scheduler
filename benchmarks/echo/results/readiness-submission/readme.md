# Readiness submission evidence

The [research report](../../readiness-submission-research.md) explains the experiments. Run `python3 summarize.py` from this directory, or invoke it by path, to validate and print every capacity median, repetition range, and per-exchange counter.

All variants start at `8400db7da957dfd7dd84de13f210c2b41a98ece1`, the merged PR #18. Builds use `cargo build --release --locked -p core-scheduler-echo-benchmark` without compiler/profile environment overrides. Each manifest records exact patches, source diffs, build commands, compiler, and frozen executable hashes.

- `worker-order-build.json` and `worker-order-matrix.json` retain the three-way, 63-sample comparison. `worker-order-loop.patch` moves only the worker's nonblocking turn; `worker-order-submit.patch` adds readiness-only combination; `worker-order.patch` is their complete source diff. The combined worker/readiness variant passes the existing Native and io_uring suites. The same Native implementation also passed the macOS coverage gate with the strengthened driver fixture; these prototype changes are not in the final staging variants.
- `deferred-build.json`, `deferred-matrix.json`, `deferred-stat.json`, and `stat/` retain the 75-sample staging matrix and ten separate counter runs. `deferred.patch` is the measured source including regressions; `deferred-production.patch` contains only runtime code. `deferred-reviewed.patch` changes only an explanatory comment after that build.
- `combined-build.json`, `combined-matrix.json`, `combined-stat.json`, and `combined-stat/` retain the final 75-sample matrix and ten separate counter runs. `combined.patch` is the measured source including regressions; `combined-production.patch` contains runtime code. The combined source includes the explanatory comment correction. `combined-reviewed.patch` unwraps added prose comments to follow Core conventions; all non-comment source lines are byte-identical to the measured source.
- `scripts/run-driver.py`, `sample-runner.py`, and `supervise.py` are the actual unchanged capacity/counter helpers, whose hashes are validated against each dataset. `stat.py` and `stat-drain.py` are the two counter runners. `build-drain.py` is the exact combined-variant build and coverage program; its hash is recorded in the build manifest.
- `verification.json` records coverage totals, test summaries, command results, and log/source hashes for the staging-only and combined variants.

The combined variant is retained in the implementation. The worker loop is unchanged. The other variants remain archived experiments. `combined-reviewed.patch` exactly matches the adopted crate-source diff against the recorded base; `verification.json` records its identity and the non-comment source hashes.

There are 233 samples in total. Each capacity matrix uses three shuffled repetitions, one second of warmup, and three measured seconds. Both counter studies use two shuffled repetitions and zero warmup; instrumented throughput is diagnostic only. Every operation acquires `/tmp/core-scheduler-perf.lock` exclusively, so builds and profiles never overlap capacity measurements. The frozen client hash is identical across all studies.

The scripts preserve their original Aiko cache and worktree paths. To reproduce an earlier variant, create an isolated checkout at the recorded base, apply its named patch, and use the recorded release command; `run-driver.py` accepts arbitrary explicit case/binary paths and a build manifest. `build-drain.py` reproduces the original combined-build transition and deliberately requires a fresh worktree. Place its input patches at the recorded cache paths or adapt those paths explicitly. Coverage uses the existing wrapper archived with [worker-loop follow-up](../worker-loop-followup/scripts/llvm-cov-wrapper.py), which excludes only the host's unavailable remapped standard-library source tree.

No executables, target directories, or binary perf recordings are included. Rejected source remains as patches, rather than enabled Cargo features.
